# Трансформация текстовых форматов

Конвертация файлов между CSV, JSON, XML и YAML. Все 12 направлений из ТЗ.

## Устройство

```
codecs/          формат: как прочитать и как записать (4 класса)
converters/      направление: читатель + проверка структуры + писатель
worker/          запуск конвертации в отдельном потоке с таймаутом
format-detector  определение исходного формата по содержимому
```

Направления не перечислены руками: `converters/index.ts` собирает все пары
разных кодеков, поэтому четыре кодека дают двенадцать направлений. Новый
формат — это один класс в `codecs/`, одна строка в `codecs/index.ts` и одно
значение в `FileFormat`; восемь новых направлений появятся сами.

## API

`POST /api/convert` — `multipart/form-data` с полями `file`,
`targetFormat` (`csv` | `json` | `xml` | `yaml`) и необязательным
`save` (`true` | `false`, по умолчанию `false`). Ответ — файл с
`Content-Disposition: attachment`.

`save=true` кладёт результат в хранилище, и его можно скачать позже из
истории — см. `src/transformations/`. Файл живёт столько же, сколько
запись истории.

Коды: `200`, `400` (битый файл или несобираемый результат), `413`
(превышен лимит для исходного формата или результат слишком велик для
сохранения), `415` (формат или направление не поддерживаются), `401`,
`429`, `500` (не удалось сохранить при `save=true`), `504` (не уложились
в таймаут).

Исходный формат определяется по содержимому; расширение имени файла —
подсказка на случай, когда содержимое неоднозначно (файл из одной колонки
без запятых одинаково подходит под CSV и под YAML).

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `CONVERT_MAX_CSV_BYTES` | 10 МиБ | лимит размера для исходного CSV |
| `CONVERT_MAX_JSON_BYTES` | 5 МиБ | то же для JSON |
| `CONVERT_MAX_XML_BYTES` | 10 МиБ | то же для XML |
| `CONVERT_MAX_YAML_BYTES` | 5 МиБ | то же для YAML |
| `CONVERT_TIMEOUT_MS` | 30 000 | сколько ждать конвертацию |
| `CONVERT_LIMIT` / `CONVERT_WINDOW_SECONDS` | 60 / 3600 | конвертаций с аккаунта |

## Правила преобразования

П. 1.4 ТЗ требует зафиксировать поведение на неоднозначных парах.
Подробности — в комментариях к соответствующим кодекам, здесь сводка.

**Общее.** Посередине любого направления лежит обычное значение
JavaScript — объект, массив, строка, число, логическое или `null`. Типы
нигде не угадываются: `007` из CSV или XML остаётся строкой `"007"`.
Глубина ограничена 64 уровнями, число значений — миллионом.

**CSV при чтении.** Первая строка — заголовок; результат — массив
объектов. Пустой заголовок получает имя `column1`, `column2`… по номеру;
повторяющиеся заголовки и разное число полей в строках — ошибка
(RFC 4180). Читаются и CRLF, и LF, и переводы строк внутри кавычек.

**CSV при записи.** Таблицей становится первый найденный массив: обёртка
с единственным ключом снимается (`{"users":[…]}` и `{"root":{"item":[…]}}`
дают одни и те же строки), иначе объект целиком — одна строка.
Вложенность разворачивается в колонки через точку (`a.b`, `tags.0`),
колонки всех строк объединяются в порядке первой встречи, `null` — пустое
поле. Пустой массив — ошибка: из него не собрать даже заголовок.

**XML при чтении.** Атрибуты получают префикс `@`, текст рядом с
атрибутами — ключ `#text`, повторяющиеся теги становятся массивом,
одиночный тег массивом не становится, объявление `<?xml?>`
отбрасывается.

**XML при записи.** Единственный ключ верхнего уровня становится корнем
(`{"note":{…}}` → `<note>`), иначе корень называется `<root>`. Элементы
массива под корнем получают имя `<item>`. Ключ, который не годится в имя
элемента XML (пробел, цифра в начале), — ошибка, а не молча испорченная
разметка.

**YAML.** Версия 1.2 и базовая схема: `no` и `yes` остаются строками, дат
в ядре нет. Якоря раскрываются, повторяющиеся ключи — ошибка. При записи
отступ два пробела, длинные строки не переносятся.

## Безопасность

- XML: сущности не раскрываются, документ с `DOCTYPE` отклоняется — это
  закрывает XXE и «billion laughs».
- YAML: число раскрытий ссылок ограничено — защита от YAML-бомбы.
- Глубина и число значений проверяются сразу после разбора: лимит на
  размер файла их не ограничивает, полтора килобайта скобок дают тысячу
  уровней вложенности.
- Разбор идёт в отдельном потоке: файл на несколько мегабайт не занимает
  основной, а зависший разбор можно прервать по таймауту — в своём потоке
  прервать `JSON.parse` нечем.
- История конвертаций пишется в общую таблицу `transformations` — ту же,
  куда пишет трансформация изображений (см. `src/transformations/`): кто,
  что, сколько байт, результат и длительность. Содержимого файлов там нет.
  Своей таблицы у модуля нет намеренно: историю обоих модулей показывает
  один список, а собрать страницу с курсором из двух таблиц нечем.
